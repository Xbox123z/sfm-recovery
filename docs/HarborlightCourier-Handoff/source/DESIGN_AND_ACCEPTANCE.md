# 设计与验收大纲

## 原创范围

从零实现一款小型 2D 城市信使游戏。只保留本地参考源码能够支持的高层因果：据点准备 → 外出完成条件目标并管理 NPC 察觉 → 撤离返家结算；噪声导致巡逻者转向调查，持续无遮挡的视觉发现导致被拦下并返家、当局未结算收益归零；长期货币/升级跨关保存。原代码的察觉、被发现和游戏结束是不同阶段，本作也不把“察觉值满”直接等同失败。新作使用自创的游戏尺度，不复用或声称复原原作数值。

恢复快照缺少完整场景/任务数据，所以关卡与数值均为本项目原创，不推断为原作地图或配置。

## 两关

- **Pierline Green（简）**：3 件包裹、1 名巡逻者、较宽的通路与较慢的视觉/噪声察觉。用于学习路线、视线遮挡、奔跑噪声和返家。
- **Glasshouse Arcade（难）**：4 件包裹、2 名巡逻者、更多建筑遮挡与更快的察觉累积。巡逻者听到奔跑后会转向上次声音来源；玩家持续处于其无遮挡视线中才会触发被拦下。
- 两关均从 Harborlight Dispatch 据点出发，在绿色 HQ 门返家。靠近包裹按互动递送；部分返家结算已记录包裹的报酬，完整递送另有完成奖励；Caught 失败会清空当局报酬并进入返家结算页。

## 画面与输入

- 以白/浅灰为底色、深色描边的方形信息卡片和按钮；地图用原创几何绘制，不含外部图像/音频/字体文件。
- Windows：鼠标选关，WASD/方向键移动，Shift 奔跑，E/空格互动，Esc 暂停。
- Android：横屏触控摇杆移动，RUN 奔跑，ACT 互动；触点可操作据点/结算按钮。

## C# 实际职责

`CourierSession.cs` 实作双关任务状态、递送计数、NPC 察觉值/失败事件分离、结算、失败损失、货币/升级和 JSON 长期存档。`CourierGame.cs` 实作场景绘制、玩家输入/碰撞、两个 NPC 巡逻与视线/噪声判定、噪声调查方向、据点 UI、触控映射与保存文件 IO。没有空壳 C++；Godot/C# 是主实现。

## 验收顺序

1. `--smoke-test`：覆盖两关配置、唯一递送、完整结算、升级、噪声察觉值满不直接失败、被发现失败损失、失败后重试、存档恢复、墙体碰撞/视线遮挡。
2. Godot Mono headless 场景启动，确认零脚本解析/运行错误。
3. Windows x86_64 导出并核对 PE 架构、嵌入数据、大小和 SHA-256；若本机无 Windows 运行时，不把静态核验冒充 Windows 实机运行。
4. Android ARM64 APK 导出并核对签名、APK 结构、原生 ABI；若无真机/模拟器，仅报告包级校验，明确未完成安装/触控验收。
5. 初始本地验收阶段只用本机已安装工具和模板，不下载依赖、不清理缓存、不推送/公开发布。若导出将超出安全空间，先停并报告具体缓存路径及大小，待批准后再继续。
